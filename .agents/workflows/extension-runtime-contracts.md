# Extension-Runtime Contracts

To ensure the Bridge remains stable, the communication payloads between the Runtime and the Extension must follow strict, predictable contracts.

## Philosophy
The contract is the law. The Extension must never send data that violates the contract. The Runtime must never send commands that violate the contract. 

## Contract Rules

### 1. The Event Envelope (Extension -> Runtime)
All messages sent from the extension to the runtime must match this structure:
```json
{
  "event": "string", // Format: "platform.domain.action" (e.g., "facebook.message.received")
  "payload": "object", // Normalized data specific to the event
  "timestamp": "number", // Unix timestamp in milliseconds
  "tab_id": "number" // Optional: The browser tab ID that generated this event
}
```

### 2. The Command Envelope (Runtime -> Extension)
All messages sent from the runtime to the extension must match this structure:
```json
{
  "id": "string", // Unique request ID generated by the Runtime
  "action": "string", // The command to execute (e.g., "click", "type", "navigate")
  "target": { // Optional: The target of the action
    "semantic": "string" // Semantic identifier resolved by the Adapter
  },
  "value": "any" // Optional: Data required for the action (e.g., text to type)
}
```

### 3. The Command Response (Extension -> Runtime)
For every Command Envelope received, the extension must eventually return a Command Response:
```json
{
  "response_to": "string", // Matches the "id" of the Command Envelope
  "status": "success" | "error",
  "data": "any", // Optional: Return data from the execution
  "error": "string" // Optional: Error message if status is "error"
}
```

## Forbidden Patterns
- 🚫 Adding ad-hoc fields to the root of the JSON payload. All custom data goes inside `payload` or `value`.
- 🚫 The Runtime sending a command without an `id`. All commands must be trackable.

## Future AI Warnings
**WARNING TO FUTURE AI**: Do not alter these base contracts without an explicit, overarching architectural review. If you need to send complex data, structure it within the existing `payload` or `value` properties. Modifying the base envelope breaks backwards compatibility and disrupts the orchestration engine.
